# 装载流程与可靠性保证

## 模块形态

模块是**预先编译好的可执行文件**（不是 `.so`），清单中用 `artifact_path` 指定。宿主在运行期将其作为子进程启动，通过 stdin/stdout 上的行分隔 JSON 通信，stderr 被截断保留用于诊断。子进程形态天然提供：

- 模块 panic / 崩溃不会进入宿主进程；
- 不同模块、不同代次之间没有符号或全局状态污染；
- 隔离后可以直接重启进程恢复。

## 清单字段

```json
{
  "module_id": "echo",
  "version": "1.0.0",
  "generation": 1,
  "min_host_generation": 0,
  "max_host_generation": 0,
  "capabilities": [],
  "artifact_path": "path/to/executable",
  "entries": [
    {"name": "echo", "input": ["string"], "output": "string"}
  ]
}
```

入口类型仅限封闭集合：`string` / `int` / `bool`。

## 一次装载事务（全有或全无）

`Host.LoadSet(manifests)` 提交的是一个**完整集合**，流程：

1. **静态校验**（不启动任何进程，纯函数、可复现）：
   - 清单结构（字段、代次正数、入口非空、无重名入口、类型合法）；
   - 代次与兼容策略、模块声明的宿主代次区间；
   - 必需能力是否齐备；
   - 集合内无重复 `module_id`、无重复 `id@gen`；
   - 与当前在线集合无相同 `id@gen`（禁止重复实例）。
2. **逐一起动进程并握手**：宿主发 `Hello`，模块发唯一一行 `Banner`。Banner 的协议、协议版本、module id、代次、入口集合与每个入口的签名都必须与清单精确一致：
   - 清单有、Banner 无 → `entry_missing`（定位到具体入口）；
   - Banner 内重名 → `entry_duplicate`；
   - 签名不一致 → `entry_type_mismatch`；
   - 模块多出未声明入口 → 同样拒绝（宿主只与声明过的入口交互）。
3. 任一模块起动或握手失败：**已起动的暂存进程全部停止**，旧集合继续完整在线，不留半装载状态。
4. 配置持久化时，先把新集合原子写入磁盘（临时文件 + fsync + rename），写失败则中止暂存集合、旧集合不变。
5. 一次原子指针交换发布新集合（对外可见的要么旧集合、要么新集合，不存在集合级/入口级混合状态），随后停止旧集合进程。

返回的错误是 `pluginhost.LoadErrors` 束，每条都带模块标识与（适用时的）入口名，拒绝原因可定位。

## 并发模型

- 装载事务之间串行（`loadMu`），但**查询与调用不拿装载锁**：它们从原子快照读取，无锁。
- 任一时刻 `Current()` 指向某个已提交的完整快照；快照不可变。
- 单个模块内调用串行化（模块级互斥），保证请求/响应严格按 ID 交替；不同模块可并发。

## 故障隔离

- 模块来源故障（handler 返回错误、handler panic 经线上报、进程退出、协议损坏、Gen2 返回违约）累计为**连续失败次数**。
- 调用方错误（入口未声明、Gen2 参数个数/类型不符）在派发到模块前拒绝，**不计**模块失败。
- 连续失败达到阈值（`host.FailureThreshold = 3`）后模块进入 `isolated`：之后调用直接返回 `IsolatedError`，不接触进程。
- 一次成功调用把计数清零。
- `Host.Query()` 可查每个模块的状态、连续失败次数、最后失败时间、原因与恢复方式。
- `Host.Recover(moduleRef)` 杀死旧进程、重新起动并完整握手，通过后回到 healthy；恢复失败原因同样可查。
- 宿主与其他模块不受任何单个模块故障影响。

## 重启恢复

配置 `host.WithPersistence(host.NewFileStore(dir))` 后：

- 每次成功提交的集合（含 set id 与全部清单）以**单文件原子替换**方式落盘，任何时刻磁盘上只有一份完整集合；
- `host.Open(ctx, ...)` 启动时若存在已保存集合，会整体恢复（恢复本身也是全有或全无事务）；恢复失败直接报错，绝不混用新旧两份；
- 被拒绝的事务从不写入磁盘。
